Conceptual architecture · Phase 1 direction

Domain model

A site is available in an installation because it belongs to the registry. Publishing attaches the current set of readable artifacts to that site; unregistering it withdraws that published set.

Current implementation boundaryThe local product discovers sites from index-directory metadata. The registered publishing workflow described here is a domain direction, not an implemented provider integration.

Objects and boundaries

The model describes product concepts independently of the actor or infrastructure that performs an operation.

SiteRegistry
Contains only registered sites. Registration creates membership; unregistering removes it. There is no separate registration entity or paused state.
Site
One logical publishing scope with a stable URL ID, a display name, and a source repository and path. Different paths in one repository may define different sites.
Artifact
A currently published HTML or Markdown document. Its source-relative path, filename, and extension are preserved. Supporting files such as CSS, JavaScript, and images are delivered but are not separate indexed artifacts.
Git source
Remains the source of truth. Unregistering withdraws the published projection; it does not delete or edit source files.

Domain operations

These names establish vocabulary; they do not prescribe process boundaries or provider APIs. The manifest-driven `registry register` command reconciles the complete registration set and cleans content prefixes for omitted sites.

OperationEffect
register(site)Adds a uniquely identified Site and its source mapping to the registry.
unregister(siteId)Removes the Site and withdraws its published Artifacts.
site.publish(artifacts)Reconciles the registered Site's published content with its source; removed source pages cease to be published.
find / list / search / browse / readObserves registered Sites and current Artifacts without mutating Git content.

Invariants and responsibilities

Membership gates publication

A publisher must match a still-registered Site's repository and source path before publishing.

No content mutation in the reader

Rename, move, delete, and content edits happen in Git, then become visible through publication.

Actors are not domain objects

Registrar and Publisher name responsibilities, not people. A person, CI job, or authorized automation may perform them.

Reader state stays local

A reader's Pin is a personal shortcut and does not change the Site or Artifact.

Registration and first publish are separate

A registered Site may temporarily have zero published Artifacts; its empty-state presentation is a UI decision.

Representations are not extra concepts

Registry YAML, browser JSON, indexes, and stored files represent this model; they are not additional domain objects.

The composition shown here expresses product availability and ownership. It does not require every site to be updated in one transaction; registration and publishing have separate coordination rules.
