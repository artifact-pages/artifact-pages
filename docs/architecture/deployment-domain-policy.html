Delivery, DNS, and certificates

Cloudflare production

The apex uses R2 custom-domain delivery with Cloudflare cache and routing/header rules. The CLI deploys the completed web bundle, registers sites in the static catalog, and publishes metadata, indexes, artifact bytes, and preview bundles to object storage.

Do not move the application to the Pages or Workers Static Assets deployment model. There is no new request-time application backend. Preserve SPA routing, real reserved-object 404s, private control-object denial, CSP, and the shared cache contract; prove their effective behavior at the real edge.

AWS verification

Create a Cloudflare DNS-only CNAME for aws.artifact-pages.dev pointing to the CloudFront distribution hostname. Do not proxy it through Cloudflare: the browser must exercise CloudFront directly, without a second CDN masking AWS behavior.

Issue the viewer certificate in ACM us-east-1, publish its DNS-validation CNAMEs in Cloudflare as DNS-only records, wait for validation, and attach the certificate and matching alias to CloudFront. Keep validation records for renewal. The S3 origin region is independent of the certificate region. Do not create a Route 53 hosted zone.

Terraform responsibility

The domain registration and authoritative zone are shared, long-lived operator prerequisites. Provider modules consume the existing zone rather than buying the domain or owning duplicate zones. Each module owns only its explicitly selected delivery records and resources; avoid two Terraform states claiming the same DNS record, zone ruleset, or lifecycle policy.

  • terraform-cloudflare-artifact-pages: R2 bucket, custom-domain connection, Cloudflare cache/routing/header rules, and provider retention. Account/zone/hostname remain caller inputs.
  • terraform-aws-artifact-pages: private S3, CloudFront/OAC, plus a composed Cloudflare DNS and ACM path for this deployment. Preserve the existing caller-managed DNS/certificate path for other operators; Cloudflare DNS is not a universal AWS prerequisite.
  • DNS and certificate orchestration belong to infrastructure adapters, not the deployment config's sites mapping, artifact records, or CLI operation semantics. Terraform does not deploy the app, register sites, or publish site documents.

The former AWS module accepts aliases and a caller-provided certificate; it does not yet prove the selected composed DNS/certificate path. IMP-39 owns that new slice. IMP-37 owns the Cloudflare entry point; IMP-38 owns independent module distribution.

Product invariants stay unchanged

  • Git is the source of truth; the browser consumes a static projection.
  • Indexes, metadata, and discovery are generated at publish time, without a request-time database or search API.
  • Provider choice does not change Site, Artifact, registry schemas, logical routes, or CLI operation meaning.
  • Production and preview HTML use the trusted same-origin execution model; Markdown remains sanitized and non-executable.
  • Viewer access remains an operator-managed edge/network concern. Public demo content must be reviewed for publication.
  • Future provider hostnames neither implement nor imply supported production adapters.
