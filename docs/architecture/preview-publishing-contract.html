Phase 1 local proof · provider-neutral contract

Preview publishing contract

A preview is an immutable, head-SHA-addressed document bundle plus a mutable, site-scoped discovery catalog. Neither is part of the production artifact index.

Local slice implemented. The focused cmd/preview-local, directory-backed store, nginx route and browser reader exercise preview development. The registered-site artifact-pages site publish path also reconciles confirmed-missing preview references after the local production projection succeeds. Preview development output at .local/previews is separate from the configured production target, commonly .local/storage. CI wrapper parity and AWS/Cloudflare provider-origin, cache, and retention proof remain open. Viewer access is configured by the operator outside Artifact Pages.

These are storage keys, not the main user navigation. The logical document route remains /:site/_previews/<headSHA>/<artifactPath>; an optional PR-group query carries reader view context without changing its revision identity or bytes. The application resolves the route to a manifest entry and then to the raw bundle file. The serving layer must keep /_previews/* separate from SPA fallback so missing raw files return an actual 404.

Minimal versioned records

Revision manifest

{
  "schemaVersion": 1,
  "site": "sre",
  "headSha": "<full Git SHA>",
  "defaultHeadSha": "<resolved default HEAD>",
  "mergeBaseSha": "<merge-base of default HEAD and head>",
  "createdAt": "<UTC timestamp>",
  "bundleDigest": "sha256:<digest>",
  "files": [
    {
      "path": "incidents/review.md",
      "sha256": "<content digest>",
      "contentType": "text/markdown"
    }
  ],
  "documents": [
    {
      "path": "incidents/review.md",
      "title": "Review",
      "format": "markdown"
    }
  ]
}

The v1 bundle digest sorts paths and hashes an eight-byte big-endian path length, UTF-8 path bytes, an eight-byte big-endian content length, and the head-tree content bytes for each file. The source bundle is kept unchanged; link mapping happens in the reader. The document list is the only set of routable preview pages. Resources are not document routes.

Discovery catalog

{
  "schemaVersion": 1,
  "site": "sre",
  "groups": [
    {
      "id": "pr:42",
      "kind": "pull-request",
      "headSha": "<full Git SHA>",
      "prUrl": "https://github.com/acme/project/pull/42",
      "updatedAt": "<UTC timestamp>",
      "documents": [
        {
          "path": "incidents/review.md",
          "title": "Review",
          "format": "markdown"
        }
      ]
    }
  ]
}

One entry per group. Only an explicitly supplied, validated PR number or URL creates a pr:<id> group; otherwise the manual group uses head:<SHA>. Two explicit PR groups can point to the same head SHA. Before showing a PR return link, the reader confirms that the named group is PR-associated and points to the route's head. If context is absent, mismatched, or unreadable, the document still renders from its manifest without a PR link. The context is preserved across changed-document navigation and dropped when navigating to production. The local reader checks static manifests; provider-origin availability checks remain unimplemented.

All paths are canonical source-relative POSIX paths with retained file extensions and URL-encoded segments in storage keys. Reject traversal, backslashes, duplicate normalized paths, symlink escapes and reserved namespaces before writing. A catalog entry is written only after its completion manifest exists; a provider lifecycle may remove that manifest later, leaving a stale discovery reference until the next catalog write.

Provider adapter boundary

The core publication flow uses a small PreviewStore contract: origin reads distinguish confirmed absence from other failures; immutable object creation never replaces different bytes; mutable catalog replacement updates one canonical key; and a cooperative per-site lock serializes preview publication with production reconciliation and unregister.

The Phase 1 DirectoryStore implements that contract with local files and a local lock. The AWS and Cloudflare adapters map their conditional writes, origin reads, and lock mechanics behind the same interface. They share schemas, routes, digest rules, and reader behavior; provider-specific serving headers, publisher IAM/credential scopes, and lifecycle retention stay in adapters and deployment configuration. Viewer access is configured by the operator at the hosting edge or surrounding network, outside the Artifact Pages product contract. This local contract does not establish live provider behavior.

Publication order

1 · PrepareResolve head/default SHAs, diff from merge-base, select A/M documents, collect resources and final bytes.
2 · Lock and validateAcquire site lock; read deployed registry directly; verify exact repository and source path.
3 · Upload bundleWrite all raw files; verify paths, bytes and content types. Do not advertise yet.
4 · Complete revisionWrite immutable manifest only after the bundle is complete. Compare existing digest on retry.
5 · DiscoverRead current catalog at origin; prune missing revisions; upsert the group; release lock.

The per-site lock serializes cooperating writers. The current adapter replaces the mutable catalog with a normal object write after revalidating the lock; this is not an atomic compare-and-swap on the catalog and does not fence an out-of-band writer. A lost lock stops the catalog write when detected. A catalog update failure is a failed pre-publish, not a successful unlisted preview. Retrying must converge without changing an already completed revision. A partially uploaded revision without a manifest is not readable through logical preview routes and is recovered by retry or retention cleanup.

no-preview is a successful no-page result for a deletion-only document change. Under the same lock it removes the group's catalog entry if present; it does not delete an earlier completed revision. A non-document-only change is an error and must not mutate discovery. Group retirement follows the same lock/read/write sequence, removes only the named group, and leaves immutable bundle objects for their remaining lifetime.

Catalog cleanup during normal publication

The local artifact-pages site publish command cleans stale discovery references in its configured target. A future optional GitHub Action is expected to call the same command; wrapper parity is tracked separately. The command reads this site's catalog and removes only PR or manual groups whose completion manifests are confirmed missing at the selected origin. A merged PR, a closed-but-unmerged PR, an open PR, and a manual preview all stay listed while their manifests exist. No source-history comparison, PR-state polling, PR-close workflow or scheduled-cleanup workflow is required.

Read and validate the catalog under the site lock; use the storage adapter to check manifest availability. For the reader's sake, write a reduced catalog only when it changed and only after the production projection is committed at origin: if production fails, previews remain discoverable. A retry repeats the same checks and converges. Catalog cleanup never deletes completed preview bundles or fixed direct URLs.

Pre-publish opportunistically prunes missing-manifest references before its own catalog upsert. Between catalog writes, the browser's Previews list and palette check manifest availability and hide missing candidates. A merged or closed-without-merging PR remains discoverable while its provider manifest exists. Manifest checks are deferred until a reader opens the site-scoped preview surface, and their cost is a release-gate measurement. An unavailable provider read is not evidence of a missing manifest: only a confirmed not-found may prune a group.

Production CLI experience

The local site publish command accepts the syntax below and its dry-run shows production changes and stale preview-catalog references together. A future CI Action tracked by IMP-34 will invoke the same operation:

$ artifact-pages site publish --site sre --dry-run
Plan for site sre via local: 4 creates, 2 updates, 1 removals.
Preview catalog: 1 stale references to prune, 4 groups retained. No writes.

A live preview is not a cleanup problem, even if it was created locally or its PR was merged or closed without merging. An unavailable provider read is not evidence of a missing manifest. A failed catalog write after a successful production update must be reported for retry rather than presented as completed cleanup.

Provider-owned retention and serving boundary

The administrator configures preview retention only in the hosting provider. Neither manifest nor catalog carries an application expiry timestamp, and the browser does not run its own expiry timer. While a completed manifest is available, a direct logical URL may resolve; after provider removal it shows “Preview unavailable”. The Previews list and palette fetch the catalog only when entered and check referenced manifest availability before showing entries. A later catalog update removes missing references. A retry of an existing revision does not overwrite its objects merely to refresh their provider lifecycle age.

Not an exact-time revocation mechanism. Provider lifecycle removal is asynchronous, and CDN caches can temporarily retain old responses. A catalog entry may therefore outlive its revision or be temporarily cached after an update. Separate bundle objects can also disappear at different times; missing raw documents and resources must return 404, never the SPA shell. A catalog under the preview lifecycle prefix expires after inactivity; each catalog rewrite refreshes only that catalog object's lifecycle age. No application-managed clock reconciles these differences.

Artifact Pages does not define public/restricted sites or viewer identities. Preview catalogs, manifests, documents and resources are static objects; any access restriction is configured and owned by the operator at the hosting edge or surrounding network. If previews should not be available to everyone admitted to the distribution, the operator's edge policy must cover their logical and raw paths. A hidden tab or unguessable SHA is not access control.

Proof before implementation is called complete

State and concurrency

  • Two different PR groups publish concurrently to one site: both remain in the catalog.
  • Same group receives two revisions: latest discoverable, both direct links stable.
  • Unregister wins first and publisher wins first: final state unregistered, no site preview objects.
  • Crash after file upload, after manifest write, and before catalog write: no broken advertised revision; retry converges.
  • Same head with different selected documents or bytes fails without replacing its manifest.
  • no-preview, provider removal, and absent catalog all produce their specified empty states.
  • Merge, squash and rebase publication leave live preview groups discoverable. Merged, closed-unmerged, open and manual groups follow the same manifest-availability rule; no app-side expiry arithmetic.
  • One publish that finds a merged PR with a live manifest, a closed-unmerged PR with a live manifest, a missing manual-preview manifest, and an open PR removes only the missing-manifest group with one catalog write. With no missing manifests, it does not rewrite the catalog.
  • Local and CI invocations with equivalent provider access produce the same cleanup result without consulting an Actions event payload, source-history comparison or PR state.
  • A failed production switch leaves previews discoverable; a successful switch followed by a catalog-write failure reports incomplete cleanup for retry without rolling back production.

Browser and provider

  • HTML iframe and Markdown reader load relative CSS, JS, images and fonts from the preview snapshot.
  • Changed-document links remain in the revision; unchanged-document links go to production without nesting the app in an iframe.
  • Missing raw resource is 404; direct logical URL works without a catalog entry while its manifest and document remain available.
  • A PR-contextual document URL shows a validated PR return link on every changed document, including after same-revision navigation; bare, manual, mismatched, and catalog-unavailable contexts render without that link. A newer revision in the group does not change an older revision's bytes or route.
  • Same-repo PR accepted, fork PR rejected before credentials; preview objects follow the same operator-managed edge boundary as the rest of the distribution.
  • Multi-page object listing and cleanup handle more than one provider page/batch without crossing site prefixes.
  • Measure lazy catalog transfer, manifest-availability checks, parse, memory and input-to-paint with many sites; opening one site's Previews must not load other catalogs.
Provider notes: S3 conditional writes, S3 lifecycle timing, and CloudFront cache expiration. These inform the AWS adapter, not the provider-neutral domain model.
