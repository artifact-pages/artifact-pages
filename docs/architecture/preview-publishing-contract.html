Post-MVP architecture · proposed contract

Preview publishing contract

A preview is an immutable, head-SHA-addressed document bundle plus a mutable, site-scoped discovery catalog. Neither is part of the production artifact index.

Design only. This page translates the product specification into a candidate static projection and failure model. It does not imply that AWS publishing, a preview CLI, or a GitHub Action has been implemented in the current local-product phase.

Objects and reads

ObjectProposed storage keyReader / lifetime
Registry/_indexes/sites.jsonPublisher validates from origin after taking the site lock; not the browser's cached copy.
Catalog/_previews/<site>/catalog.jsonBrowser fetches only on that site's Previews surface. Mutable; absent means no discoverable previews.
Revision manifest/_previews/<site>/revisions/<headSHA>/manifest.jsonBrowser resolves a direct preview URL through this completion marker, independently of the catalog. Written last within a revision; immutable while retained.
Bundle files/_previews/<site>/revisions/<headSHA>/files/<source-relative path>Changed documents and their copied local rendering resources. Relative CSS, JS, image and font paths stay relative under files/.
Site lock/_control/locks/<site>.jsonShared by production publish, pre-publish and unregister. Never publicly served.

These are storage keys, not the main user navigation. The logical document URL remains /:site/_previews/<headSHA>/<artifactPath>; the application resolves it to a manifest entry and then to the raw bundle file. The serving layer must keep /_previews/* separate from SPA fallback so missing raw files return an actual 404.

Minimal versioned records

Revision manifest

{
  "schemaVersion": 1,
  "site": "sre",
  "headSha": "<full Git SHA>",
  "comparisonBaseSha": "<resolved default HEAD>",
  "createdAt": "<UTC timestamp>",
  "bundleDigest": "sha256:<digest>",
  "files": [
    {
      "path": "incidents/review.md",
      "sha256": "<content digest>",
      "contentType": "text/markdown"
    }
  ],
  "documents": [
    {
      "path": "incidents/review.md",
      "title": "Review",
      "format": "markdown"
    }
  ]
}

The digest covers a canonical sorted list of every bundle path and its final published bytes, including rewritten links. The document list is the only set of routable preview pages. Resources are not document routes.

Discovery catalog

{
  "schemaVersion": 1,
  "site": "sre",
  "groups": [
    {
      "id": "pr:42",
      "headSha": "<full Git SHA>",
      "updatedAt": "<UTC timestamp>",
      "documents": [
        {
          "path": "incidents/review.md",
          "title": "Review",
          "format": "markdown"
        }
      ]
    }
  ]
}

One entry per group. PR groups use pr:<id>; manual defaults use head:<SHA>. The group is a discovery identity, not part of the revision URL. Entries are candidates: the reader checks whether their revision manifests still exist at the provider.

All paths are canonical source-relative POSIX paths with retained file extensions. Reject traversal, backslashes, duplicate normalized paths, symlink escapes and reserved namespaces before uploading. Catalog entries never point to a revision without a completion manifest.

Publication order

1 · PrepareResolve head/default SHAs, diff from merge-base, select A/M documents, collect resources and final bytes.
2 · Lock and validateAcquire site lock; read deployed registry directly; verify exact repository and source path.
3 · Upload bundleWrite all raw files; verify paths, bytes and content types. Do not advertise yet.
4 · Complete revisionWrite immutable manifest only after the bundle is complete. Compare existing digest on retry.
5 · DiscoverRead current catalog at origin; prune missing revisions; upsert the group; release lock.

The lock serializes cooperating writers; an atomic conditional write on the mutable catalog is still useful as a defensive check against an out-of-band writer. A catalog update failure is a failed pre-publish, not a successful unlisted preview. Retrying must converge without changing an already completed revision. A partially uploaded revision without a manifest is not readable through logical preview routes and is recovered by retry or retention cleanup.

no-preview is a successful no-page result for a deletion-only document change. Under the same lock it removes the group's catalog entry if present; it does not delete an earlier completed revision. A non-document-only change is an error and must not mutate discovery. Group retirement follows the same lock/read/write sequence, removes only the named group, and leaves immutable bundle objects for their remaining lifetime.

Catalog reconciliation during normal publication

artifact-pages site publish owns catalog reconciliation whether a person runs it locally or GitHub Actions invokes it. It reads this site's current catalog and applies two predicates to each group: a PR group is retired when its source PR is closed (merged or unmerged), and any PR or manual group is pruned when its completion manifest is absent at provider origin. Open PRs and manual groups with available manifests stay listed. Because the catalog already carries PR identity, looking backward from newly merged commits is unnecessary for cleanup. One set of removals produces one conditional catalog write; no separate PR-close or scheduled-cleanup workflow is required.

Read and validate the catalog under the site lock. The CLI orchestrates a source-host adapter for PR state and a storage adapter for manifest availability, so the same checks can run locally with equivalent credentials. Identify candidates before mutating production. For the reader's sake, write the reduced catalog only after the production projection is committed at origin: if production fails, previews remain discoverable. A retry repeats the same checks and converges. Catalog retirement never deletes completed preview bundles or fixed direct URLs.

Pre-publish opportunistically prunes missing-manifest references before its own catalog upsert. Between catalog writes, the browser's Previews list and palette check manifest availability and hide missing candidates. A PR closed without merging and without a subsequent production publish can remain discoverable while its provider objects exist; no browser-side GitHub state polling or extra workflow is required. Manifest checks are deferred until a reader opens the site-scoped preview surface, and their cost is a release-gate measurement. Whether a GitHub lookup failure should fail the production operation or merely defer retirement remains a technical policy to settle before implementation.

The GitHub Action is a thin, separately distributed wrapper: for pre-publish it checks same-repository PR identity before obtaining publisher credentials; for production publish it provides checkout and credentials and invokes the same CLI operation available locally. It returns CLI outputs and does not own catalog reconciliation, PR comments, or workflow timing. A dry-run computes and reports the document/resource set and intended catalog change without provider writes. Exact flag and Action input spellings are deferred until the CLI surface is implemented; this table fixes meaning, not syntax.

Provider-owned retention and serving boundary

The administrator configures preview retention only in the hosting provider. Neither manifest nor catalog carries an application expiry timestamp, and the browser does not run its own expiry timer. While a completed manifest is available, a direct logical URL may resolve; after provider removal it shows “Preview unavailable”. The Previews list and palette fetch the catalog only when entered and check referenced manifest availability before showing entries. A later catalog update removes missing references. A retry of an existing revision does not overwrite its objects merely to refresh their provider lifecycle age.

Not an exact-time revocation mechanism. Provider lifecycle removal is asynchronous, and CDN caches can temporarily retain old responses. A catalog entry may therefore outlive its revision or be temporarily cached after an update. Separate bundle objects can also disappear at different times; missing raw documents and resources must return 404, never the SPA shell. A catalog under the preview lifecycle prefix expires after inactivity; each catalog rewrite refreshes only that catalog object's lifecycle age. No application-managed clock reconciles these differences.

For a restricted site, authorization applies to the catalog, manifest, documents and resources before any shared-cache response. Public pre-merge previews are public for a public site. Neither a client-side hidden tab nor an unguessable SHA is an access control.

Proof before implementation is called complete

State and concurrency

  • Two different PR groups publish concurrently to one site: both remain in the catalog.
  • Same group receives two revisions: latest discoverable, both direct links stable.
  • Unregister wins first and publisher wins first: final state unregistered, no site preview objects.
  • Crash after file upload, after manifest write, and before catalog write: no broken advertised revision; retry converges.
  • Same head with different selected documents or bytes fails without replacing its manifest.
  • no-preview, production retirement, reopen, provider removal, and absent catalog all produce their specified empty states.
  • Merge, squash, and rebase publication retire their recorded PR groups by PR state even when the preview head differs from the default-branch commit. A closed-unmerged PR is retired on a later production publish; a still-open PR or manual group whose provider manifest disappears is removed in the same catalog reconciliation without any app-side expiry arithmetic.
  • One publish that finds a newly merged PR, a previously closed PR, a missing manual-preview manifest, and an open PR removes exactly the first three groups with one catalog write; the open PR remains.
  • Local and CI invocations with the same source-host and provider access produce the same reconciliation result without consulting an Actions event payload.
  • A failed production switch leaves its PR previews discoverable; a successful switch followed by a catalog-write failure reports the incomplete retirement for retry without rolling back production.

Browser and provider

  • HTML iframe and Markdown reader load relative CSS, JS, images and fonts from the preview snapshot.
  • Changed-document links remain in the revision; unchanged-document links go to production without nesting the app in an iframe.
  • Missing raw resource is 404; direct logical URL works without a catalog entry while its manifest and document remain available.
  • Same-repo PR accepted, fork PR rejected before credentials; restricted site denies every preview object consistently.
  • Multi-page object listing and cleanup handle more than one provider page/batch without crossing site prefixes.
  • Measure lazy catalog transfer, manifest-availability checks, parse, memory and input-to-paint with many sites; opening one site's Previews must not load other catalogs.
Provider notes: S3 conditional writes, S3 lifecycle timing, and CloudFront cache expiration. These inform the AWS adapter, not the provider-neutral domain model.
