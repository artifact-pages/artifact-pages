Artifact Pagesを社内に導入し、各チームが資料を公開できる環境を提供するためのガイド。

32 pagesupdated Oct 16, 2026·
README.md

チームが自分たちで公開できる、資料の共有基盤を。

各チームがGitで管理する資料を、自分たちのリポジトリから公開します。管理者は共通の基盤を運用し、読者は同じ閲覧画面で資料を探して読めます。

導入すると、こう運用できます

  • 基盤・閲覧アプリの更新と、各サイトの公開を分けて運用できます。
  • チームはPRで変更をプレビューし、自分のサイトを独立して公開できます。
  • 読者はフォルダ、検索、目次から必要な情報へ進めます。

最初の公開から、社内への展開まで

まずは導入手順に沿って、インフラ構築から最初のサイトの公開・プレビューまでを確かめます。構築後はチームへの展開と運用へ進んでください。

採用前に仕組みや費用を確認する場合は、アーキテクチャから読むこともできます。

公開元は、各チームのリポジトリ

資料とその変更履歴はチームのGitリポジトリで管理します。他のサイトの公開を待つことなく、チームのタイミングで更新できます。

共通基盤の管理者と各サイトの公開担当者が、それぞれの担当範囲を理解して運用できるようにします。導入手順では最初のサイトで確認し、その手順をチーム向けの案内へつなげます。

PRで確認してから公開する

本公開の前に、変更した資料の表示とリンクを確認します。プレビューと公開中のサイトを使い分けてレビューします。

共通基盤の管理者と各サイトの公開担当者が、それぞれの担当範囲を理解して運用できるようにします。導入手順では最初のサイトで確認し、その手順をチーム向けの案内へつなげます。

フォルダとREADMEで資料を整理する

章ごとにディレクトリを分け、その目的と読み始め方をREADMEに記述します。HTMLの資料も公開できます。
