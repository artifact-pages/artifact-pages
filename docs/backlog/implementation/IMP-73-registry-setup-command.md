# IMP-73 — `registry setup` command and admin templates

- Status: In progress

- Owner: Codex (CLI)

## Goal

Generate the admin-side files of the official site onboarding path (TD18 contract items 1, 2, 3 and 7), so an operator does not hand-write them.

## Scope

- `artifact-pages registry setup [--check] ...` idempotently generates `.github/workflows/publish-site.yml`, `.github/workflows/preview-site.yml`, `.github/actions/site-sync/action.yml` and the admin registry workflow from a local deployment config. It does not consume `terraform output` or emit a per-site role map. `artifact-pages registry role-arn --config FILE --site ID` derives the selected AWS role ARN from an explicit local config at runtime.
- AWS setup requires `aws.accountId`; `aws.namePrefix` is optional and defaults to `artifact-pages`. The CLI and `terraform/modules/aws` use the same name rule: `<prefix>-<site>-publisher` up to 64 characters, otherwise `<prefix>-s-<first 20 lowercase hex characters of SHA-256(site ID)>-pub`. A shared fixture exercises the boundary in both Go and a Terraform mock test. The generated AWS composite checksum-verifies the official CLI release selected by the generator and runs the local-only role helper against `${{ github.action_path }}/../../../artifact-pages.yaml`; it reads no secret and makes no AWS or GitHub API call. The CLI v0.4.0 source candidate is now published.
- The reusable workflows take a required string input `site` and an optional string input `environment`. Separate conditional jobs set the caller repository's environment only when non-empty; the alternate job has no environment. They map Cloudflare secrets to `env` and declare only the provider-specific minimum permissions; the preview job keeps the same-repository PR guard and its `pull-requests: write` permission. The composite action reads `${{ github.action_path }}/../../../artifact-pages.yaml` (`$GITHUB_ACTION_PATH` works only in shell steps, not in `with: config:`) and calls the official Action with `config` set to that file.
- Each generated file has a header naming the CLI version and pins each official Action to an exact release (full SHA with a version comment) following TD17's independent Action series. This item decides where the generator gets those versions.
- Empty `environment` semantics: generated publish and preview workflows route to a separate job without an `environment:` key when the input is omitted or empty. The other job sets the caller repository's named environment. The generated registry job retains the operator's existing PR dry-run behavior by selecting `production` only outside `pull_request` events.
- `--config` is a local regular file under `--directory`; it may not traverse a symlink. Generated destinations are fixed under that root, and existing unmanaged files are never silently overwritten. Cloudflare and AWS Action pins are embedded in source so setup is offline. When regenerating an older AWS setup, the command removes `aws-roles.json` only if the prior generated action's managed digest and its recorded map digest both match; `--check` reports this migration as drift without modifying either file.
- `--check` exits non-zero when committed files differ from the generated ones.
- The command prints the remaining manual steps as copyable `gh` commands (Actions access level for private admins, secrets) and performs no GitHub API mutation.
- Specification §19/§22 and the command tree document `registry setup` and `registry role-arn`; both local-only commands bypass config resolution, downloads, re-execution and bootstrap metadata.
- AWS `namePrefix` is emitted by the Terraform config output only when `name_prefix` is non-default. A custom prefix is an operationally breaking role-name change. Published Action v0.2.0 bootstraps CLI 0.4.0 and declares `cliRange: ">=0.4.0 <0.5.0"`, so generated workflows with v0.2.0 Action pins accept the current writer CLI. The IMP-75 fixture used generator CLI 0.3.0 and writer CLI 0.2.0 historically; operator repositories subsequently adopted Actions v0.2.0 and CLI 0.4.x (T15).
