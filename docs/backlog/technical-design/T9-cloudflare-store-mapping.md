# T9 — Cloudflare preview store and lock mapping

- Status: Done
- Phase: Post-MVP provider deployment

## Design question

Which Cloudflare storage, origin-read, and cooperative-lock capabilities should implement the provider-neutral `PreviewStore` contract? Keep the canonical records, object keys, immutable/mutable semantics, publication order, and site-scoped lock contract shared with the local and AWS implementations.

## Selected mapping

- Store preview records and files in Cloudflare R2 through its S3-compatible API at `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, with region `auto`. `internal/publisher.ObjectPreviewStore` adapts the shared object and conditional-write interface to the domain-level `preview.PreviewStore`; preview keys and publication rules remain provider-neutral.
- Use R2 `GetObject` for origin reads, `PutObject` with `If-None-Match: *` for immutable files/manifests, and the same retained `_control/locks/sites/<site>.json` ETag compare-and-swap record used by registered site publication. Use `PutObject` for the mutable catalog while holding that lock.
- Serve public static objects through the R2 custom domain selected in [T12](T12-cloudflare-production-mapping.md); keep logical-route rewrites, `_control` denial, cache rules, and any customer-managed edge access configuration in the deployment, outside the preview store and domain model.
- Translate only confirmed missing-key responses to `ErrObjectNotFound`. Authorization, transport, malformed response, and partial-list errors remain failures. The shared adapter follows every `ListObjectsV2` continuation page and checks each batched delete response.
- Preview catalog objects use short mutable cache freshness; revision manifests and files keep bounded revalidation until retention and delivery verification settle. R2 object-lifecycle policy owns removal; the application does not write expiry timestamps.
- Immutable create-once writes use `If-None-Match: *`. If a retry receives a precondition failure, read the existing object: identical bytes mean the retry already succeeded; different bytes are an immutable revision conflict. Complete all bundle objects before the manifest, and write the catalog only after the manifest.
- Mutable catalog replacement is an ordinary `PutObject` under the site lock. The shared adapter requires a lock-bearing context, then rereads and validates the held lock's site, owner, and ETag immediately before replacement. If ownership changed, fail without writing the catalog; completed immutable objects remain unadvertised and a retry reacquires the lock and replans. The catalog write is not atomic with the preceding lock read, so lock recovery remains cooperative: an operator must confirm no publisher is active and use the inspected ETag. Locks do not expire automatically.
- Keep provider responsibilities outside the preview domain: [IMP-18](../implementation/IMP-18-cloudflare-preview-adapter.md) owns Cloudflare adapter behavior; [IMP-14](../implementation/IMP-14-provider-serving.md) owns routes/cache configuration and [T4](../verification/T4-serving-boundary.md) owns delivery/cache proof; viewer access remains customer-managed at the edge. [IMP-15](../implementation/IMP-15-provider-retention.md), [T3](T3-provider-retention.md), and [T8](../verification/T8-stale-reference-cleanup.md) own retention and stale-catalog behavior; [T5](../verification/T5-concurrency-recovery.md) owns lock/retry evidence. [T12](T12-cloudflare-production-mapping.md) and [T15](../verification/T15-provider-delivery.md) keep live Cloudflare storage and edge proof separate.

The official R2 compatibility table currently lists `GetObject`, `HeadObject`, `PutObject`, `ListObjectsV2`, and conditional `If-Match`/`If-None-Match` operations. That is a capability match, not a real-service race proof. See [R2 S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/) and [R2 error codes](https://developers.cloudflare.com/r2/api/error-codes/).

## Exit criteria

- [x] Select the Cloudflare services and credentials for object storage, static serving, and per-site locking without introducing Cloudflare-specific concepts into the preview domain model.
- [x] Map confirmed object absence separately from access, transport, and partial-listing failures.
- [x] Define safe immutable create-once and mutable catalog replacement behavior, including retry and lock-loss semantics.
- [x] Link adapter, serving, and retention decisions to [IMP-18](../implementation/IMP-18-cloudflare-preview-adapter.md), [IMP-14](../implementation/IMP-14-provider-serving.md), [IMP-15](../implementation/IMP-15-provider-retention.md), and T4/T5/T8 evidence.

## Evidence

`internal/publisher.ObjectPreviewStore` implements the shared immutable-write, mutable-catalog, origin-read, and site-lock mapping over `publisher.ConditionalObjectBackend`; reconciliation decisions remain in `internal/preview`. Tests cover idempotent immutable writes, changed-byte conflicts, catalog retry and lock loss (`TestObjectPreviewStorePublishRetriesMutableCatalogReplacement`, `TestObjectPreviewStoreStopsCatalogWriteAfterLockLossAndCanRetry`), missing lock-context rejection (`TestObjectPreviewStoreRequiresLockContextForCatalogReplacement`), and site-publish recovery before preview reconciliation (`TestPublishSiteRejectsPreviewReconciliationAfterLockRecovery`). Provider-adapter fakes now also exercise AWS concurrency/lock loss and Cloudflare retry, concurrent groups, interruption, and lock loss; their live account semantics remain open in IMP-12/18. The shared S3-compatible adapter maps `NoSuchKey` to confirmed absence but leaves `NoSuchBucket` and unclassified 404 errors intact; AWS's ambiguous `HeadObject` 404 uses an exact-key origin-list confirmation. Cloudflare documents conditional `PutObject` operations and returns `412 PreconditionFailed` when a condition is not met ([compatibility table](https://developers.cloudflare.com/r2/api/s3/api/), [error codes](https://developers.cloudflare.com/r2/api/error-codes/)). That is API-surface evidence, not proof of live R2 races. [IMP-18](../implementation/IMP-18-cloudflare-preview-adapter.md), [T12](T12-cloudflare-production-mapping.md), [T15](../verification/T15-provider-delivery.md), [IMP-32](../implementation/IMP-32-cloudflare-production-adapter.md), and [IMP-33](../implementation/IMP-33-cloudflare-deployment.md) retain the live R2 and deployed-edge acceptance gates.
