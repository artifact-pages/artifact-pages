# T5 — Concurrency and recovery

- Status: In progress
- Phase: Phase 1 local proof; provider recovery remains post-MVP

## Contract to prove

The shared site lock and retry-safe catalog replacement preserve the Phase 1 publication boundary and keep discovery consistent through local concurrent publishes, retries, and interrupted uploads. Provider conditional lock/immutable-object writes and cross-process recovery remain adapter verification gates; mutable catalogs use an ordinary write while the cooperative site lock is held, as settled in [T9](../technical-design/T9-cloudflare-store-mapping.md).

## Exit criteria

- [x] Run two concurrent preview group updates on one site against the local `PreviewStore`.
- [x] Run both actual preview-publish/unregister orderings after the registered-site preview publication path is introduced ([IMP-16](../implementation/IMP-16-unregister.md), Post-MVP).
- [x] Run both normal site publish/registry unregister orderings against a deterministic local backend.
- [x] Verify a second process waits on a held local site lock and can acquire it after release.
- [x] Inject failure after bundle upload, after manifest completion, and before catalog update; retry without advertising an incomplete revision.
- [x] Reject a same-head retry that changes selected documents or bytes.
- [x] Retry a same preview head after only the default-branch HEAD advances, retaining revision provenance and discovery group context.
- [ ] Exercise provider conditional lock/immutable-object races and stale-lock recovery without losing an unrelated group's catalog update.

## Evidence

The local writer verifies an existing immutable manifest and each stored file's bytes on same-head retry, rejects changed bytes, selected documents, or merge-base, writes the manifest only after its files, and updates discovery afterward. `TestBuildFromGitSameHeadRetryAfterDefaultBranchAdvances` builds both attempts from a real Git fixture: advancing an unrelated file on the default branch changes `DefaultHead` while preserving the preview head, merge-base, selected documents, and bundle. The retry plan retains every object and reports no catalog changes; applying it preserves the original completed-manifest bytes and provenance, makes no immutable-object writes, and leaves the original discovery group timestamp intact. `internal/preview/store_test.go` deterministically overlaps two group updates and proves both survive; it also covers no-preview removal, missing-versus-unavailable manifest pruning through catalog upsert, and partial bundle, manifest, and catalog failures converging on retry without advertising an incomplete revision. `internal/publisher/preview_adapter_test.go` additionally verifies concurrent same-site group publications through `ObjectPreviewStore` and the shared provider-neutral conditional-backend fake: both catalog groups and immutable objects survive, while another site's preview prefix and lock remain unchanged (`TestObjectPreviewStoreConcurrentGroupsKeepBothCatalogAndIsolateOtherSites`). This fake test exercises shared lock orchestration, not provider-specific conditional-write behavior. `internal/preview/git_test.go` verifies a resource-only change leaves an existing local catalog unchanged through `BuildAndPublish`. The normal site publisher and registry unregister also have deterministic local tests for both interleavings (`internal/publisher/site_publish_test.go`). The registered preview publisher now has its own both-orderings tests (`internal/publisher/preview_publish_race_test.go`): publish-first finishes under the site lock before cleanup, while unregister-first withdraws eligibility and rejects the waiting preview publisher with zero upload attempts. `TestDirectoryBackendSiteLockCoordinatesAcrossProcesses` verifies `syscall.Flock` blocks a second process until the current holder releases the local site lock. AWS fake listing tests cover complete multi-page unregister and a second-page failure that performs no deletion before retry (`TestUnregisterSiteCleansEveryAWSListingPageWithFakeBackend`, `TestUnregisterSiteRetriesAfterAWSContinuationListingFailure`); `internal/publisher/preview_adapter_test.go` also covers a partial preview listing failure that performs no deletion before a successful retry. Provider lock recovery and conditional catalog races remain open. See the [proof matrix](../../architecture/preview-publishing-contract.html#proof).

The AWS preview integration tests compose `awsBackend` with `ObjectPreviewStore` over a deterministic in-memory S3 API fake. `TestAWSPreviewIntegrationRevalidatesOriginRegistryBeforeUploading` proves the publisher reads the origin registry after taking the S3-backed site lock and rejects an unregistered site before preview uploads. `TestAWSPreviewIntegrationRetriesInterruptedUploadWithoutCrossSiteWrites` injects a manifest upload failure after file completion, then verifies a same-head retry preserves completed object bytes and ETags, uses S3 conditional lock and immutable-create requests, and leaves a neighboring site's prefix and lock unchanged. This is provider-adapter fake evidence; it does not prove live S3 race or lifecycle behavior, so the remaining provider lock-recovery and conditional-write gate stays open.

The adapter fakes now also exercise two concurrent AWS preview groups, AWS lock loss before catalog publication, and Cloudflare/R2-compatible interruption retry, concurrent groups, lock loss, and site isolation through `ObjectPreviewStore` (`TestAWSPreviewIntegrationConcurrentGroupsKeepBothCatalogAndIsolateOtherSites`, `TestAWSPreviewIntegrationRejectsCatalogWriteAfterLockLossWithoutCrossSiteWrites`, and the three `TestCloudflarePreviewIntegration...` cases). The Cloudflare concurrency case pauses the first publication inside an immutable-object PUT, proves the second publisher observed the held site lock and made no writes while waiting, then confirms both groups remain in the catalog after release. The focused and full publisher race tests pass. Cloudflare uses a local S3-compatible HTTP endpoint, not an R2 account; real AWS/R2 conditional-write and recovery behavior remains unverified.

The lock wait bound now also covers repeated conditional-write conflicts without a caller deadline. `TestLockCASConflictsRespectWaitLimitForSiteAndRegistry` covers first-create and free-lock acquisition conflicts for both site and registry scopes, while checking bounded polling instead of busy-spinning. `TestLockCASConflictHonorsCallerCancellation` checks prompt cancellation, and `TestInterruptedSiteLockWaitsUntilGuardedRecovery` checks the same elapsed bound for an already-held lock. `go test -race ./internal/publisher -count=1` passes these regressions together with the existing independent-site and guarded-recovery tests. This closes the local ISSUE-021 defect; provider-specific conditional-write behavior remains a separate proof gate.
