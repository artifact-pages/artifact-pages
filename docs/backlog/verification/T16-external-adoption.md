## Proof needed

The operator repositories `artifact-pages/admin` and `artifact-pages/docs` already run released Actions for `artifact-pages.dev` ([TD5](../technical-design/TD5-verification-environment-and-operator-repositories.md)), but they are the project's own deployments. This ticket needs a clean consumer: a new public repository with its own Cloudflare bucket and hostname (environment chosen by the owner, decision D8) that follows only the public guide (artifact-pages.dev/guide) and released artifacts. CLI, web and each Action are versioned independently ([TD17](../technical-design/TD17-config-pinned-component-versions.md)); the Terraform module is versioned per module ([TD15](../technical-design/TD15-terraform-module-source-of-truth.md)).

- [ ] Select each deliverable independently from released artifacts only, without copying OSS application or infrastructure source: CLI release binaries (`v0.2.0` or later) verified against the release checksums; the web bundle `web/v0.1.0` or later; the four Actions (`publish-action`, `preview-action`, `registry-action`, `app-deploy-action`, currently `v0.1.0`) pinned by exact `vX.Y.Z` tag or that tag's full commit SHA, as [TD4](../technical-design/TD4-action-marketplace-distribution.md) documents; and the Cloudflare module from `artifact-pages/terraform-cloudflare-artifact-pages` at its first tag, via a Git source (after IMP-64). Record the resolved module commit and provider versions. Registry retrieval is a separate, later item after [IMP-38](../implementation/IMP-38-terraform-registry-publication.md); a Git source proves the package repository, not Registry adoption.
- [ ] Confirm the CLI and web versions come from the admin config (`cli.version`, `web.version`), not from the Action pin: the published Actions install a bootstrap CLI that downloads and re-executes the version named by `cli.version`, and `app deploy` installs the bundle named by `web.version`. Verify bundle integrity, install/deploy, complete-manifest `registry sync` dry-run/apply, site dry-run/publish, and that an Action run matches the CLI run.
- [ ] Run the released Actions on a GitHub-hosted runner from the separate public repository, using the documented exact-tag or SHA reference. The preflight job must complete before the provider job requests credentials.
- [ ] Upgrade and roll back one web version (`web.version`) with `app deploy` without changing site objects. Prove that changing `cli.version` in the config does not require repackaging or redeploying the web app, and verify the selected schema versions.
- [ ] Follow the guide end to end, including the provider setup page, and record every point where the consumer had to leave it. Start live adoption with Cloudflare; its deployed delivery proof remains T15. Keep AWS evidence separate and required before an AWS support claim; its readiness must not block the Cloudflare proof.
