Git Artifact Pages · UI concept review

Make the artifact easy to find, trust, and read.

The product promise is a normal web experience for Git-managed artifacts. These concepts use the same SRE data and the same deep-link route, but put a different part of that promise first.

A · WorkbenchPersistent navigation for daily exploration. B · Reading RoomArtifact content gets the visual priority. C · LaunchpadDiscovery starts with recent work and search.
Concept A

The Workbench

Keep the artifact tree, rendered content, and table of contents visible together. This is the most direct expression of the target three-pane layout in the specification.

Wins when reviewers move between several related artifacts and need orientation more than uninterrupted reading.

Concept B

The Reading Room

Treat the artifact as a calm document-reading surface. Navigation becomes a slim rail, metadata stays close to the title, and the rendered page gets a paper-like canvas.

Wins when artifacts are long-form documents and the reader should forget the platform exists once the page is open.

Concept C

The Launchpad

Make the site home the primary product: search across the index, scan recent artifacts, and jump into a known piece of work. The reader view can become a focused second step.

Wins when users arrive with a vague goal such as “find the latest incident review” rather than a URL or exact title.
