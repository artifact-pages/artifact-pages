読者向け

読者の体験

公開された文書は、URLを開くだけで読めます。このページでは、画面の見方と、読みながらページやサイトを探す方法をまとめます。

URL

URLには、サイトのIDと、公開元でのファイルの場所をそのまま使います。ファイル名と拡張子もURLに残るので、リンクを共有しても再読み込みしても、同じ文書が開きます。

URL開くもの例
/サイトの一覧/
/<サイト>サイトのトップページ/checkout
/<サイト>/<パス>文書/checkout/design/payment-flow.html

例のサイトとパスは説明用です。index.htmlも、ほかの文書と同じくファイル名まで指定して開きます。フォルダのURLを開いても、index.htmlは自動では開きません。

画面の構成

左にサイトのナビゲーション、中央に文書、右に必要なときだけ開くパネルがあります。

  1. サイト：いま読んでいるサイト。押すとほかのサイトを選べます。
  2. Pinned：ピン留めした文書。自分のブラウザにだけ保存されます。
  3. Browse：フォルダ構成のまま並んだ文書。上の欄で絞り込めます。
  4. 文書：HTMLは公開されたままの見た目で、Markdownはアプリが整えて表示します。
  5. Contents / Details：目次と、最終更新や公開元の情報。文書に重ねて開きます。

文書が多いサイトでは、サイドバーとトップページにRecently updated（最近更新された文書）も表示されます。

検索とサイトの切り替え

⌘K / Ctrl Kでコマンドパレットを開きます。記号を付けずに入力すると、いま読んでいるサイトの中だけを、タイトルとパスで検索します。探す対象は、先頭に付ける記号で次のように変わります。

入力探すもの
（記号なし）いまのサイトの文書。文書を開いているときは、その文書の見出しとコマンドも候補に出ます。
@サイト。選ぶと、そのサイトのトップページへ移ります。
#開いている文書の見出し。
>コマンド（テーマの切り替え、リンクのコピーなど）。

文書を探すときは、パレット上部のタブで範囲を絞れます。All（すべて）、Recent（最近読んだ文書）、Pinned（ピン留め）、Previews（プルリクエストのプレビュー）です。

複数のサイトをまとめて検索する機能はありません。別のサイトの文書は、@でサイトを移ってから探します。

試してみる

下の見本は、このガイドと説明用のサイトで作ったものです。「検索を試す」か左の欄を押して、文字や@を入力してみてください。

JavaScriptを有効にすると、ここで検索とサイトの切り替えを試せます。

HTMLとMarkdown

HTMLは、公開されたファイルをそのまま表示します。文書自身のCSSやJavaScriptもそのまま動くので、レポートやダッシュボード、図も作ったときの見た目で読めます。

Markdownは、アプリが読みやすく整えて表示します。表、チェックリスト、脚注などのGitHub形式の書き方と、Mermaidの図に対応しています。埋め込まれたHTMLは安全のために一部が取り除かれ、スクリプトは動きません。

どちらの形式でも、同じサイトのほかの文書へのリンクを押すと、アプリの中で移動します。

目次と詳細

文書の上部にあるContentsとDetailsを押すと、右側にパネルが開きます。文書の幅は変わりません。

  • Contents：文書の見出しの一覧です。押すとその見出しへ移ります。
  • Details：最終更新日、その変更をコミットした人、公開元のリポジトリとファイルへのリンクです。コミットした人は最後の変更の記録で、文書を最初に書いた人とは限りません。

ブラウザに残るもの

ピン留め、最近読んだ文書（サイトごとに最大20件）、テーマ（ライト・ダーク・システム設定に合わせる）は、いま使っているブラウザにだけ保存されます。ほかの人や別の端末には共有されず、公開された文書やリポジトリも変わりません。

文書の内容を変えるときは、公開元のGitリポジトリで変更します。
