Git から、読める Web へ

Gitにある成果物を、読むための場所へ。

HTMLもMarkdownも、Gitに置いたまま、URLで読めて検索できる。 Git Artifact Pages は、Gitで管理している文書を静的なサイトとして公開し、サイトを選び、ページを探し、リンクで共有できる閲覧体験を届けます。

読者は、サイドバーからページを選び、⌘K / Ctrl K の検索でページを探し、@ でサイトを切り替えます（JavaScriptを有効にすると、ここで動きを確認できます）。

画面は、このガイド自身のページと説明用の例で構成した見本です。

01
そのまま公開

HTMLとMarkdownを、ファイル名と拡張子ごと。URLは /サイト/ファイル名.html の形で、そのまま共有できます。

02
チームごとのサイト

チームやプロダクトごとに、独立した閲覧先を持てます。1つのGitリポジトリのディレクトリが、1つのサイトになります。

03
すぐ見つける

ページは ⌘K / Ctrl K で検索、@ でサイトを切り替え。索引は公開時に作られます。

しくみ

公開から閲覧までの流れ

01 / アプリを配置 管理者

まず、読むためのアプリを置く。

管理者が、静的な閲覧アプリ（SPA）を配信先へ一度だけデプロイします。これがすべてのサイトに共通する入口です。公開済みのWebリリースを取得して検証してから、アプリ本体のファイルだけを書き込みます。

ターミナル / 管理者
# まず変更計画だけ確認（何も書き込みません）
$ artifact-pages app deploy --version x.y.z --dry-run
# 反映
$ artifact-pages app deploy --version x.y.z

x.y.z には公開済みリリースのバージョンを指定します。配信先の設定は --config、または管理リポジトリの artifact-pages.yaml から解決されます。サイトの索引や文書には触れません。

02 / サイトを登録 管理者

次に、サイトを登録する。

サイトは、チームごとに持つのが基本です。同じチームでも、プロダクトごとに分けられます。サイトには、ID、表示名、元になるGitリポジトリ（owner/repo）とディレクトリ（sourcePath）があり、管理者が設定ファイルに書いて登録します。まだ文書がなくても登録できます。

artifact-pages.yaml / 管理リポジトリ
sites:
  sre:
    name: SREチーム
    repository: acme/sre-handbook
    sourcePath: docs/public
  checkout:
    name: 決済チーム / Checkout
    repository: acme/checkout
    sourcePath: docs/artifacts
  billing:
    name: 決済チーム / Billing
    repository: acme/billing
    sourcePath: docs/artifacts
ターミナル / 管理者
$ artifact-pages registry register --dry-run
$ artifact-pages registry register

sites 全体が「登録するサイトの完全な一覧」です。ここから外したサイトは、次の registry register で登録解除され、公開済みの内容も削除されます。配信先（provider）の設定は省略しています。

03 / Git から公開 各チームのリポジトリ

各Gitリポジトリから、担当サイトへ公開する。

各チームのGitリポジトリが、担当するサイトと公開するディレクトリを明示して公開します。公開のたびに索引を作り、HTMLとMarkdown、CSSや画像をそのまま配置します。

ターミナル / acme/checkout
# docs/artifacts を、サイト checkout へ
$ artifact-pages site publish --site checkout --source docs/artifacts --dry-run
$ artifact-pages site publish --site checkout --source docs/artifacts

書き込む前に、配信先に登録されたリポジトリ・ディレクトリと一致するかを確認します。他のサイトには書き込みません。マージ時に CI から同じコマンドを実行する運用を想定しています。

04 / 開いて探す 読者

そして、普通のURLで読む。

読者はURLを開くだけです。読んでいる途中でも ⌘K / Ctrl K で、いまのサイトのページや見出しを検索できます。@ を打つと、ほかのチームのサイトへ切り替えられます。

ブラウザ / 読者
→ https://<配信ドメイン>/checkout/design/payment-flow.html
⌘K / Ctrl K   このサイトのページと見出しを検索
@             サイトを切り替え

URLはファイル名と拡張子を保持するので、文書へのリンクをそのまま共有できます。<配信ドメイン> は、管理者が配信先に選んだアドレスです。

Git → Web / いま見えている構成01 / 04
共通の閲覧アプリが、みんなの読む場所になります。チームやプロダクトごとに、公開先のサイトを登録します。各チームのリポジトリが、自分のサイトへ成果物を送ります。読者はURLを開き、検索して、次の文書へ進みます。

使用例

チームのサイトを開くと、こう見えます。

決済チームの checkout サイトのトップページ（説明用の例）。⌘K のあと @ で、ほかのチームのサイトへ移れます。

サイトを移るときは、⌘K / Ctrl K のあと @。 チームやプロダクトごとのサイトが並び、選ぶとそのサイトのトップページが開きます。

Gitが正本。Webは読む場所。

検索、ナビゲーション、ピン留めは閲覧体験のためのもので、内容の変更はGitで行います。HTMLは信頼できる公開元の文書として扱い、閲覧者のアクセス制御は配信側で設定します。図や設定に出てくるチーム・リポジトリ（acme/…）は説明用の例です。
