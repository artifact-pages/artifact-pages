公開するチーム向け

サイトの公開

各チームは、自分のGitリポジトリにある1つのディレクトリから、自分のサイトを公開します。このページでは、そのディレクトリに置くもの、site syncコマンド、CIからの実行、プレビューを説明します。

前提

始める前に、次の2つが必要です。artifact-pagesコマンドと、管理者があなたのリポジトリとディレクトリに対して登録したサイトです。サイトのIDと使う設定ファイルは、管理者に確認してください。

artifact-pagesのCLIはGitHub Releasesで配布しています。以下の例では、acme/checkoutのdocs/artifactsから公開する、説明用のcheckoutサイトを使います。

公開するもの

1つのサイトの中身は、1つのリポジトリの1つのディレクトリです。管理者がsourcePathとして登録したディレクトリがそれにあたります。ディレクトリの中身はそのまま公開されるので、配信できる状態になっている必要があります。公開時にサイトジェネレーターを動かしたり、テンプレートを展開したり、CSSやJavaScriptをまとめたり、リンクを書き換えたりはしません。ジェネレーターを使う場合は、その出力先のディレクトリを公開します。

acme/checkoutのdocs/artifacts/読者が開くURL種類
design/payment-flow.html→/checkout/design/payment-flow.htmlページ
design/refund-states.md→/checkout/design/refund-states.mdページ
design/img/flow.svg→参照するページが読み込むリソース
incidents/2026-09-12-timeout.html→/checkout/incidents/2026-09-12-timeout.htmlページ
index.html→/checkout/index.htmlページ
assets/report.css→参照するページが読み込むリソース
  • .html、.htm、.mdのファイルは、どのフォルダにあってもすべてページになります。index.htmlも、_includes/のようなフォルダの中のファイルも同じです。テンプレートや部品のファイルは、ディレクトリの外に置いてください。
  • index.htmlは普通のページです。/checkoutを開くと表示されるのはサイトのトップページで、index.htmlではありません。
  • それ以外のファイルは、公開されますが一覧には出ません。CSS、JavaScript、画像、フォント、JSONなどです。ページからはimg/flow.svgや../assets/report.cssのような相対リンクで読み込みます。/assets/report.cssのように/から始まるリンクはサイトの外を指すので、読み込めません。
  • ページのタイトルは、HTMLなら<title>、Markdownなら最初の#見出しから取ります。どちらもなければファイル名を使い、payment-flow.htmlは「Payment Flow」になります。
  • 更新日とコミットした人はGitの履歴から取ります。作業ツリーで変更・追加したファイルは、ファイルの更新時刻がコミットの日時より新しければ、その時刻を更新日にします。Gitが無視するファイル（生成物など）も公開されます。その更新日は、ページのディレクトリ（その下を含む）にあるファイルのうち最も新しい更新時刻で、コミットした人は表示されません。
  • シンボリックリンクがあると公開は失敗します。.gitフォルダは公開されません。
確認

ディレクトリにあるファイルは、どのページからもリンクされていなくても、公開すれば読めます。秘密情報や内部メモ、下書きは置かないでください。また、HTMLは公開したとおりに動くので、信頼できるHTMLだけを公開します。詳しくは「信頼とアクセス制御」を参照してください。

site syncで公開する

登録したリポジトリをチェックアウトした場所で実行します。まず--dry-runで変更内容を確かめてから公開します。

ターミナル / acme/checkout
# 何が変わるかを確認（何も書き込みません）
$ artifact-pages site sync --site checkout --source docs/artifacts --dry-run
# 公開する
$ artifact-pages site sync --site checkout --source docs/artifacts
  1. インデックスを作る

    ディレクトリを読み、タイトル、見出し、日付などのページのインデックスを作ります。

  2. 登録を確認する

    配信先からサイトの登録情報を読みます。リポジトリとディレクトリが登録と一致しなければ、何も書き込みません。

  3. 同期する

    新しいファイルと変わったファイルを送り、インデックスを差し替え、最後にディレクトリから消えたファイルを削除します。

  4. キャッシュを更新する

    変わったURLのキャッシュの更新をCDNに依頼します。

リポジトリは、チェックアウトしたGitのリモートからowner/repoの形で判定します。書き換えるのは自分のサイトだけで、ほかのサイト、サイトの登録情報、閲覧アプリには触れません。1つのサイトで同時に動く公開は1つだけです。

オプション内容
--site ID必須登録されたサイトのID。リポジトリ名から推測はしません。
--source DIR任意公開するディレクトリ。リポジトリのルートからのパスが、登録したsourcePathと一致する必要があります。省略すると登録されたパスを使います。
--config LOCATOR任意配信先を指定する設定ファイル。省略したときの選ばれ方は「設定ファイル」を参照してください。
--dry-run任意書き込み、削除、キャッシュ更新の依頼をせずに、変更内容だけを表示します。
--format text|json任意jsonにすると、変更の全一覧を返します。CI向けです。

テキストの出力は、先頭に結果（DRY RUN、SYNCED、UP TO DATE）を示し、追加・更新・削除したパスをグループごとに最大12件まで並べます。終了コードは、計画・公開・変更なしのとき0、オプションや設定が不正なとき2、公開に失敗したとき1です。

本文検索

site syncは、閲覧アプリの本文検索が使う静的データも毎回作って公開します。そのサイトの読者は、サイドバーの検索欄と⌘⇧Fを使えます。

ターミナル / acme/checkout
$ artifact-pages site sync --site checkout --source docs/artifacts
自動

追加のオプションは不要です。site sync は毎回検索データを公開します。以前のCLIで公開したサイトには、現在のCLIで site sync を実行すると検索データが追加されます。

検索の対象は、HTMLならタイトルと静的な本文、Markdownならタイトルと表示される本文（コードブロックを含む）です。スクリプトが作る文字、画像のalt、パスは対象外です。CSSで隠しただけの文字は対象になります。ナビゲーションのように毎ページ繰り返す文字を除くには、その要素にhidden、aria-hidden="true"、data-search-ignoreのいずれかを付けます。

読者に反映されるまで

  • 一度には切り替わりません。ファイルを送り、次にインデックスを差し替え、最後に古いファイルを消します。公開の途中では、読者に古い内容と新しい内容が混ざって見えることがあります。
  • キャッシュ。配信側のCDNは、サイトのインデックスを最大60秒、ページを最大300秒キャッシュすることがあります。公開時には、変わったURLの更新をCDNに依頼します。
  • 開いている読者。すでにサイトを開いている人は、再読み込みするとサイドバーに新しいページが出ます。
  • 失敗したとき。原因を直して同じコマンドをもう一度実行すれば、残りの変更が反映されます。自動で元に戻す機能はないので、戻すときは前の内容をもう一度公開します。

CIから実行する

CIで同じコマンドを動かすのが基本の運用です。プルリクエストでは--dry-runだけを実行し、マージ後に公開します。どのブランチから公開してよいかはワークフロー側で決めます。サイトの登録情報にブランチの設定はありません。

  1. プルリクエストで：変更を確認する

    読み取り専用の認証情報で、--dry-runを付けて実行します。JSONの結果に、変わる内容がすべて出ます。

    CI / プルリクエスト
    $ artifact-pages site sync --site checkout --source docs/artifacts --dry-run --format json

  2. マージ後に：公開する

    このサイトだけに書き込める認証情報で、--dry-runを外して実行します。

    CI / デフォルトブランチ
    $ artifact-pages site sync --site checkout --source docs/artifacts --format json
  • 認証情報はCIのシークレットに置き、設定ファイルには書きません。公開のジョブに必要なのは、サイトの登録情報の読み取りと、このサイトのファイル・プレビュー・ロック・キャッシュ再試行の記録（_control/sites/<site>/site-cache.json）の読み書き、それにCDNのキャッシュ更新の依頼だけです。「設定ファイル」を参照してください。
  • 管理者の設定ファイルを写す必要はありません。--configに、コミットを固定したgithub://の指定で管理リポジトリのファイルを渡せます（リモートの設定ファイル）。公開してよいかどうかは、その場合も配信先にある登録情報で確認します。
  • GitHub Actions。このリポジトリには、同じコマンドを包む任意のActionもあります。

プレビュー

プレビューを使うと、公開中のサイトを変えずに、マージ前の変更をレビュアーが読めます。公開とは別のコマンドpreview publishを使います。

ターミナル / acme/checkout（プルリクエスト#42）
$ artifact-pages preview publish --site checkout --source docs/artifacts --base-url https://docs.example.com --pull-request 42 --dry-run
$ artifact-pages preview publish --site checkout --source docs/artifacts --base-url https://docs.example.com --pull-request 42

--base-urlは閲覧アプリのアドレスで、返すリンクを組み立てるのに使います。https://docs.example.comは説明用の例です。--site、--source、--base-urlは必須です。

対象になるもの

デフォルトブランチ（--default-ref、既定はorigin/HEAD）から分かれたあと、ヘッド（--head、既定はHEAD）で追加・変更されたHTMLとMarkdownのページと、それらが読み込むファイルです。

変更していないページへのリンクは、公開中の版を開きます。削除したページのプレビューはありません。スクリプトが実行時に名前を組み立てるリソースは--include PATHで追加します。

読者が見つける場所

各ページは/checkout/_previews/<ヘッドのSHA>/design/payment-flow.htmlのようなURLになります。サイトのトップページのView previewsと、パレットのOpen previewsから一覧を開けます。

プレビューは、Browse、検索、Recently updatedには出ません。

  • プルリクエスト。--pull-request（番号かPRのURL）を付けると、そのPRのプレビューとしてまとめられ、PRへ戻るリンクが表示されます。PRは登録したリポジトリ自身のブランチから出ている必要があり、フォークからのPRは受け付けません。付けなければ、PRのリンクがない手動のプレビューになります。
  • リンクの共有。コマンドはプレビューのURLを返します（--format json）。PRにコメントするかどうかは、ワークフロー側で決めます。
  • 保持と削除。同じPRで新しいプレビューを作ると一覧では置き換わりますが、古いURLは保持ルールで削除されるまで開けます。1つのグループと専有するすべてのリビジョンを消すには、preview remove --site checkout --group pr:42を実行します。兄弟グループのオリジンデータは削除しません。サイト単位のキャッシュ更新で、兄弟グループのキャッシュ応答も更新されることがあります。保持期間は管理者がクラウド側で設定します。
  • 信頼。プレビューのHTMLは、レビューが終わる前から公開済みのHTMLとまったく同じように動きます。プレビューは信頼できるブランチからだけ作ってください。

公開に失敗したとき

状況対処
サイトが登録されていないエラーに登録済みのサイトIDが並びます。--siteと設定ファイルの配信先を確かめるか、管理者にサイトの登録を依頼します。
「registered to … selected checkout is …」リポジトリかディレクトリが登録と違います。登録したリポジトリのチェックアウトで、登録したディレクトリを指定して実行します。
公開元にシンボリックリンクがある実体のファイルに置き換えるか、ディレクトリの外へ移します。
サイトのロックが取られている同じサイトの site sync、プレビュー操作、または registry sync のクリーンアップが実行中です。しばらくして再実行します。途中で止まった実行がロックを残した場合は、管理者がlock inspect --siteで確認し、lock recoverで解除します。
一部を変更したあとで失敗した原因を直して同じコマンドをもう一度実行します。残りの変更が反映されます。
