# Existing-bucket delivery submodule

Connects an existing private R2 bucket to the Artifact Pages custom-domain delivery contract. This module does not create the bucket or configure lifecycle expiration.

It creates or manages the R2 custom domain and owns zone phase-root rulesets for logical route rewrites, origin-respecting cache settings, the trusted-HTML Content Security Policy on raw `/_artifacts/<site>/*` and `/_previews/<site>/revisions/<sha>/files/*` objects, and an `http_config_settings` rule that disables body-rewriting edge features (email obfuscation, Rocket Loader, Automatic HTTPS Rewrites, Fonts, RUM and Zaraz injection, Markdown for Agents, Polish) for the configured hostname only, so published bytes are delivered unchanged. The rule needs the `Config Rules Edit` zone permission; `existing_config_rules` preserves operator rules in that root, and `config_ruleset_name` names an imported root. It can also own the custom-firewall phase when `waf_custom_rules` is non-null. It does not manage the alternate `r2.dev` domain; a newly created private R2 bucket keeps that domain disabled by Cloudflare's default. For an existing bucket, verify and disable `r2.dev` in Cloudflare before exposing the bucket through the custom domain. An enabled `r2.dev` URL bypasses these hostname rewrite rules and could expose private `/_control/*` objects. Unmatched paths—including `/_control/*`—on the configured hostname rewrite to `/index.html`. Preview HTML stays on the application origin, is intended for an ordinary unsandboxed iframe, and receives the same trusted executable-content policy as production HTML. The CSP includes the object's site or revision path plus HTTPS sources, blocks insecure HTTP, and adds no CORS grant. See the root [module README](../../README.md#resource-ownership-and-apply-review) before applying. In particular, import and preserve each complete existing zone phase root before managing it, including its immutable name.

`waf_custom_rules` defaults to `null`, which leaves the WAF phase unmanaged. A non-null policy must compose at least one rule and takes ownership of the complete `http_request_firewall_custom` root. Supply existing root rules in `existing_rules`, then optional presets and new provider-native `rules`; these are composed in that order. Existing rules keep their fields and expressions unchanged. Caller expressions and generated presets are scoped to the configured lowercase hostname. The HTTPS preset blocks an unencrypted request or a request received on a port other than 443. The IP preset blocks source addresses outside its valid, non-empty IPv4/IPv6 CIDR list. If both are active, one generated Block rule uses OR between their violations, admitting requests only when every preset passes.

The rule collections use an opaque ordered input so rules with different Cloudflare provider attributes—such as `ratelimit`, `logging`, and `action_parameters`—can remain heterogeneous. The module validates non-empty string `ref`, `expression`, and `action`, unique/reserved refs, and the final 4,096-character expression limit after host wrapping. Cloudflare validates action/phase semantics, provider-specific fields, and account entitlements. `enabled = false` disables generated and caller rules while leaving imported rules unchanged. The WAF root has `prevent_destroy`; keep the policy configured with at least one rule while it is managed. Removing the resource/module block entirely also removes that protection. WAF creation requires `Zone WAF Write`; check rule/ruleset limits and plan-specific actions before planning.

The custom-domain resource cannot be imported. Set `connect_custom_domain = false` only when an existing connection is managed and verified separately.

`/LICENSE` and `/THIRD_PARTY_NOTICES.txt` are application-bundle objects, not logical reader routes. Their case-normalized paths bypass the SPA rewrite and use the origin's cache headers. After deploying a bundle, verify that these URLs return the actual license/notice text; a 200 response containing the app shell is not successful notice delivery. Missing notice objects must remain origin 404s. These exceptions do not change the `/_control/*` SPA fallback or configure authentication or Cloudflare Access.

This submodule uses Terraform `>= 1.5.0, < 2.0.0` and Cloudflare provider `>= 5.24.0, < 6.0.0`. It can be selected from a consumer repository with the Cloudflare module Git URL and `//modules/delivery?ref=<full-commit-sha>`.

The `transform_ruleset_name`, `cache_ruleset_name`, `response_header_ruleset_name`, and `config_ruleset_name` inputs default to descriptive Artifact Pages names for new phase roots. When importing an existing root, set the corresponding input to its current name before planning; changing a ruleset name requires replacement. For WAF, set `waf_custom_rules.ruleset_name` to the imported name and supply the complete existing rules through `existing_rules`.
